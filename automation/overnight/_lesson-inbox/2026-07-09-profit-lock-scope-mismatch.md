# Lesson candidate: same exit-shape dict, two engines, different SCOPE for one knob (research fills-authority vs live decision core)

**Symptom:** Building the vwap entry/exit matrix (2026-07-09), the same control cell (-6%/+40%/0.8/fixed, profit-lock arm +5%) produced pnl=0.0 breakeven scratches in `simulate_trade_real` on trades where the `exit_manager`-based replay of the SAME trade took the full -6% stop. Every ratified vwap exit scorecard (vwapcont-exit-parity.json 2026-07-02, vwapcont-exit-ab-ship-gate.json 2026-07-07) passed `profit_lock_threshold_pct=0.05` believing it mirrored the live shape.

**Root cause:** `simulator_real.py:540-584` arms the profit-lock on ANY favorable touch — pre-TP1 included, where the ratcheted `runner_stop_premium` IS the exit-ALL stop — while `exit_manager.plan_exit_actions` only armed the lock at/after TP1 (and since the TP1 fill itself set `profit_lock_armed=True`, `profit_lock_arm_pct` was an unreachable/dead knob in live). Not a dead knob (C14) — a knob WIRED on both sides with DIFFERENT SCOPE: the same shape dict means two different trades depending on which engine reads it. The 2026-07-02 parity study's own comment ("what an isolated-exit override would ACTUALLY trade") shows the false premise was believed, not checked.

**Fix (2026-07-09):** (1) `exit_manager`/`ExitShape` gained an expressible `profit_lock_arm_scope` field — `post_tp1` default = byte-identical legacy live behavior, `full` = simulator parity — armed by NO live shape (arming needs a live-machine scorecard + STOP-B). (2) Cross-machine pins that RED on SILENT convergence from either side: `backtest/tests/test_profit_lock_scope_pin.py` (pins the sim's pre-TP1 scratch) + `automation/state/fleet/test_exit_manager.py::test_pre_tp1_lock_*` (pins the live default + vary-and-asserts the full scope; red-proofed). (3) Both scorecards annotated with `sim_semantics_caveat`; magnitude quantified by the matrix isolation test (lock component ≈ -$0.72/tr aggregate on vwap — real per-trade, roughly EV-neutral aggregate; the -$39.71/tr cross-engine gap is mostly OTHER divergences: ribbon-flip modeling, fill conventions). (4) Standing rule re-affirmed: exit-shape RATIFICATION numbers come from `exit_manager` replay (t4/t5/matrix precedent); `simulate_trade_real` stays the discovery/signal authority.

**Generalization:** when research and live share a config vocabulary, every knob needs a SCOPE-parity check, not just a wired-at-all check (C14's sharper sibling). The guard pattern: pin each engine's semantics in its own test suite with docstrings cross-referencing the twin, so converging them is forced to be a conscious, scorecard-backed decision in one commit — never a silent "fix" that re-bases every historical study. Also: a study comment asserting "this mirrors live" is a claim to VERIFY against the live core's code, not prose to inherit.
