## ⛔ DESCRIPTIVE ONLY — read this first

This ledger **measures**; it validates **nothing**. It carries **no pass/fail gates, no
ship decision, no stop-placement recommendation**. MAE knowledge is hindsight by definition
(C6: you only know a trade's maximum heat after it resolved — a live stop cannot condition
on it). Any stop-placement change is its OWN future pre-registered A/B that may CITE this
ledger as its evidence base. That is this artifact's entire job.

Because there is no hypothesis to freeze, what this prereg freezes is the **method** — so
the definitions cannot drift toward whatever makes a later study look good.

## Frozen definitions

Let `entry` = qty-weighted entry premium, `Q` = entry qty (contracts). Walk window `W` =
**exit-eligible holding window**: bars strictly AFTER the entry bar's minute through the
final-exit-fill bar inclusive (`winner_autopsy.bars_between` — the entry+1 convention,
`markdown/audits/ENTRY-BAR-CONVENTION-RULING-2026-07-25.md`; reused, not reimplemented).

| Field | Definition |
|---|---|
| `min_low` / `max_high` | min bar low / max bar high over `W` |
| `mae_pct` | `min(0, min_low/entry − 1)` — ≤ 0 always; 0.0 = never adverse |
| `mfe_pct` | `max(0, max_high/entry − 1)` — ≥ 0 always; 0.0 = never favorable |
| `mae_dollars_entry_qty` | `mae_pct × entry × Q × 100` (≤ 0) — **labelled**: heat at full entry size; hypothetical if the MAE bar postdates a partial exit (see flag) |
| `mfe_dollars_entry_qty` | `mfe_pct × entry × Q × 100` (≥ 0), same label |
| `time_to_mae_min` | minutes, entry bar → FIRST bar printing `min_low`; None when `mae_pct==0` |
| `time_to_mfe_min` | minutes, entry bar → FIRST bar printing `max_high`; None when `mfe_pct==0` |
| `mae_before_first_exit` | MAE bar minute strictly BEFORE the first exit fill's bar minute (validity flag for the $ figure) |
| `stop_premium` | `entry × (1 + premium_stop_pct)` from the **as-configured-at-the-time** shape: as-placed `placement` block ▷ arm `exit_patch` ▷ engine default (−50% catastrophe cap) — `winner_autopsy.resolve_shipped_shape`, reused |
| `stop_inside_mae` | `min_low ≤ stop_premium` (touch counts) — "price traded through the configured premium-stop level during the holding window" |
| outcome | `winner` pnl>0 · `loser` pnl<0 · `scratch` pnl==0 |

## Disclosed limitations (frozen now so they can't become excuses later)

- **Bar-low basis:** 1-min bar lows see every intra-minute trade; the live actuator samples
  one NBBO snapshot per ~minute. `stop_inside_mae` therefore means "level traded through",
  NOT "live would have fired". Bias direction: overcounts touches vs live behavior.
- **Entry-bar exclusion (entry+1):** heat inside the entry bar's own minute is invisible to
  the live exit pass and is excluded here to match; disclosed, not zero.
- **Structure-mode stops:** where `stop_mode=="structure"`, the recoverable premium stop is
  the −50% catastrophe cap, not the operative chart stop — rows carry `stop_basis` so no
  reader mistakes one for the other.
- **$ figures at entry qty** — see flag above.
