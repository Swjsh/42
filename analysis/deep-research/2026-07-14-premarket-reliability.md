# Gamma_Premarket reliability audit -- last 3 weeks (2026-06-23..2026-07-14)

**Read-only audit. No config changed, no orders placed.** Sources: `automation/state/logs/premarket-{date}.log` (per-fire wrapper log, exists since 2026-05-06), `automation/overnight/STATUS.md` self-check entries (`PREMARKET STALE` / `PREMARKET SILENT FAILURE` lines), `automation/state/circuit-breaker.json` + `automation/state/aggressive/circuit-breaker.json` (`_note` field + git history), `journal/trades.csv` (real-world trading impact), `git log` on `automation/state/today-bias.json` / `circuit-breaker.json` / `key-levels.json`.

**Verdict up front: did NOT silently die for 2 weeks straight.** Today's own premarket fire (2026-07-14, logged in `today-bias.json`'s `bias_note`) reported "premarket has not written fresh state in 2 weeks" -- that framing is **not what the evidence shows**. `today-bias.json` refreshed successfully on **9 of 16** trading days in the window, including as recently as 2026-07-10. What's real and worse in one respect: a **recurring intermittent failure** (4 full misses + 2 unconfirmed + 1 late-night-only miss = 7 of 16 trading days degraded) **plus a separate, more alarming mechanism** -- something periodically reverts `automation/state/*.json` files back to old git-committed content mid-session, which is what produced the "stale-dated 06-30" read this morning (see Finding 2 below).

## Trading kept working through premarket failures

`journal/trades.csv` cross-check for the days above: **06-29 (unconfirmed premarket) had 4 real trades; 07-09 (confirmed full-day premarket failure) had 13 real trades.** This corroborates the standing architecture doctrine (`project_heartbeat_core_deterministic` memory: "pure-Python see->decide->act; no LLM/MCP on hot path") -- `heartbeat_core.py` reads live TV/VIX/structure directly and does **not** gate entries on `today-bias.json`'s qualitative narrative. Premarket failures degrade the **human-readable context layer** (bias note, falsifiable predictions, the morning brief J reads) and, on late-recovery days, leave a stale bias sitting in the file for the engine to nominally "see" -- but they have not been shown to block real order flow. 07-13/07-14's zero-trade mornings are **not** shown to be caused by the premarket miss (could equally be no valid setup firing) -- flagged as correlation, not claimed as causation.

## Finding 2 -- a separate, more concerning mechanism: state files reverting to old git-committed content mid-session

`circuit-breaker.json`'s own `_note` field today reads: *"Re-armed 2026-07-14 premarket (DETERMINISTIC fallback -- daily_loss_guard.rearm; prior stamped date was 2026-06-26)."* But the SAME day's log shows the breaker was **already** correctly rearmed twice earlier that morning (08:30 `REARMED prior_date=2026-07-13`, 08:36 `already_armed_today`) -- both consistent with a clean day-to-day chain. Then the 09:15 rearm reports `prior_date=2026-06-26`, a date **18 days stale**, matching `circuit-breaker.json`'s own last **git-committed** snapshot (`git log` -- last commit touching this file is `667217a`, dated around 2026-06-26). Something reset the file's on-disk content back to its last-committed state **between 08:36 and 09:15 on 2026-07-14**, erasing the correctly-armed intervening state.

This is not an isolated read: a Job-1-adjacent finding already on `STATUS.md` (`[2026-07-14] FUTURES-MIRROR-SHADOW extended`) independently found `automation/state/core-decisions.jsonl` and 3 of 4 fleet arms' `decisions.jsonl` sitting byte-identical to their last git commit (`667217a`, 2026-06-26) despite `Gamma_HeartbeatCore` reporting `LastTaskResult=0` every day since -- same date, same symptom, different file. That entry already flagged this for a dedicated `/fable-differential` session (git-reflog archaeology) and this audit does not re-open that investigation -- but it directly explains why today's premarket fire (and `today-bias.json`'s own `bias_note`) reported "stale-dated 2026-06-30": whatever reset the state directory made the files LOOK like they hadn't moved since late June, even on days (07-02, 07-07, 07-08, 07-10) where the logs prove they had. **The "2-week outage" framing in today's `today-bias.json` is most likely this reset event caught mid-flap, not a continuous 2-week failure** -- the log evidence says the last confirmed-fresh write before today was 2026-07-10, not 2026-06-30.

## Root-cause signature of the LLM-step failures

- **07-13 + 07-14 (waves 1-2):** `API Error: 400 All target providers failed` / `Not logged in - Please run /login` -- both are **CCR (claude-code-router) / auth-layer** failures, not market-data or TradingView issues. Same failure class both days, back to back.
- **06-30:** a bare silent failure (exit 0, no bias) -- different signature, no error text captured in that era's log format.
- **07-03:** exit 0 but empty `falsifiable_predictions` -- the LLM ran and "succeeded" but produced no usable content. A third distinct failure shape.
- **06-25 / 06-29:** logs truncate mid-attempt with no terminal marker at all -- consistent with the reaper killing the process before either a completion or a timeout line could be written (`_shared.ps1#Stop-StaleClaudeProcesses`, the standing CLAUDE.md scar).

Three genuinely different failure mechanisms (auth/routing outage, hollow-success, and reaped-silent) all currently degrade to the exact same downstream symptom: a stale `today-bias.json`. No single fix (e.g. "handle the CCR outage") closes the gap for the other two shapes.

## The deterministic gap -- spec, not build (per JOB 3b scope)

The breaker-arm half of Gamma_Premarket is **already deterministic and reliable**: `setup/scripts/daily_loss_guard.rearm()` hits the Alpaca REST equity endpoint directly (no LLM, no MCP), and every log in this window that reaches a REARM line shows `exit=0`/`ok=true` -- including on 07-09 and 07-13, the two confirmed full-day LLM failures. **The gap is entirely on the bias/levels narrative side** (`today-bias.json`'s qualitative content: direction, key levels, falsifiable predictions, the human-readable brief) -- that has zero fallback and depends 100% on a successful Claude Code fire.

Given a 25-44% miss rate over 3 weeks (by the two read conventions above) and 3 distinct root-cause shapes, this is material. Proposed shape for a deterministic fallback (**spec only, not built this session**, per instructions):

1. **Trigger:** the existing wrapper's own retry-exhaustion path (already detects `today-bias.date != today` after all LLM attempts fail) calls a new pure-Python `premarket_deterministic_fallback.py` instead of leaving the stale file in place.
2. **Inputs:** `sight_beacon.py`'s already-un-blockable SPY REST+yfinance read (per `project_never_blind_sight_beacon` doctrine) + a VIX read via the same path + the prior session's close/PMH/PML from cached bars -- zero new data dependencies, reuses infra already proven to survive the exact outages (CCR/auth, TV-down) that kill the LLM step.
3. **Output shape:** a **structurally minimal, mechanically-derived** `today-bias.json` -- e.g. `bias="neutral_no_llm"`, key levels from the prior day's H/L/close only (no fresh trendline/ribbon read -- that needs the chart), zero falsifiable predictions (don't fabricate a qualitative call the fallback can't back), `vix_bias` from the raw VIX print against the existing static thresholds.
4. **Degraded marking (non-negotiable):** every field the fallback writes gets `"source": "deterministic_fallback"` at the top level and `"degraded": true`, so nothing downstream (dashboard, journal, any future consumer) can mistake it for a real qualitative premarket read. The existing `PREMARKET SILENT FAILURE` / `PREMARKET STALE` self-checks should be updated to distinguish "stale" (fallback never ran either) from "degraded-fresh" (fallback covered for the LLM) -- currently both would read as the same `date == today` and look identical to a real fresh write.
5. **Does NOT attempt:** chart-based levels, ribbon/EMA stack, trendline reads, or any TradingView-dependent signal -- those need the chart and have no deterministic substitute; the fallback's job is "not blind," not "as good as the LLM read."
6. **Cost:** $0 (no LLM call), runs in seconds, fires only on confirmed retry-exhaustion -- no added daily cost per CLAUDE.md OP-3's cost-discipline gate.

This is a spec, not a build -- per JOB 3b's explicit instruction, no code was written for this fallback in this session.
